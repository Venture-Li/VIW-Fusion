# VIW-Fusion 汇报材料

---

## 一、视觉SLAM分类

### 1.1 按后端优化方式分类

| 类型 | 代表算法 | 特点 |
|------|---------|------|
| **滤波方法** | MSCKF, ROVIO, OpenVINS | 基于EKF，计算量小，适合资源受限平台；但线性化误差累积，精度受限 |
| **优化方法** | ORB-SLAM, VINS-Mono, OKVIS | 基于BA/因子图，精度高；计算量大，需GPU或高性能CPU |
| **直接法** | DSO, SVO | 直接使用像素强度，不依赖特征点；对光照变化敏感 |

### 1.2 按传感器组合分类

| 类型 | 传感器 | 特点 |
|------|--------|------|
| **纯视觉** | 单目/双目/RGB-D | 单目无尺度，双目有尺度但基线限制，RGB-D范围受限 |
| **视觉-惯性(VIO)** | 相机+IMU | IMU提供尺度和重力方向，互补视觉在纹理缺失场景的不足 |
| **视觉-惯性-轮速(VIW)** | 相机+IMU+轮速计 | 轮速计提供绝对尺度约束，解决退化运动问题 |

### 1.3 按应用场景分类

- **室内/小场景**: ORB-SLAM2/3, DSO — 回环检测重要
- **车载/大场景**: VINS-Mono/Fusion, VIW-Fusion — 实时性、鲁棒性优先
- **AR/VR**: MSCKF, ROVIO — 低延迟、高频输出
- **无人机**: VINS-Mono/Fusion — 快速运动、大视差

## 二、车载场景对实时性和精度的要求

### 2.1 实时性要求

| 指标 | 要求 | 原因 |
|------|------|------|
| 位姿输出频率 | ≥10Hz | 下游规划/控制模块需要高频反馈 |
| 单帧处理时间 | <100ms | 保证不丢帧，维持实时性 |
| 初始化时间 | <5s | 车辆启动后快速进入定位状态 |

### 2.2 精度要求

| 场景 | 精度要求 | 说明 |
|------|---------|------|
| 高速巡航(>60km/h) | 相对误差<1% | 长距离累积误差需控制 |
| 城市道路(20-60km/h) | 相对误差<2% | 转弯、加减速场景 |
| 低速/停车(<20km/h) | 绝对误差<0.5m | 泊车场景精度要求最高 |

### 2.3 车载场景特殊挑战

1. **退化运动**: 直线匀速行驶时，尺度不可观（单目VIO的核心问题）
2. **动态环境**: 大量运动车辆、行人造成外点
3. **光照变化**: 隧道、夜间、逆光等极端光照
4. **纹理缺失**: 路面、白墙等无纹理区域
5. **快速运动**: 高速行驶时图像模糊、特征跟踪困难
6. **转弯激励不足**: 长直道缺乏旋转激励，IMU偏置估计退化

## 三、选择VINS算法的原因

### 3.1 为什么选VINS而非ORB-SLAM

| 对比维度 | VINS-Mono/Fusion | ORB-SLAM3 |
|---------|-----------------|-----------|
| **传感器** | 紧耦合VIO，IMU+视觉联合优化 | 松耦合，IMU仅用于初始化后不再参与优化 |
| **初始化** | 视觉-惯性联合初始化，恢复尺度/重力/速度/偏置 | 纯视觉初始化，IMU仅辅助 |
| **鲁棒性** | IMU持续提供约束，纹理缺失时仍可短时推算 | 依赖视觉特征，纹理缺失时易丢失 |
| **尺度** | IMU提供绝对尺度 | 单目无尺度，需额外信息 |
| **实时性** | 滑动窗口固定计算量 | 局部BA计算量随地图增长 |
| **车载适配** | 紧耦合更适合车载动态场景 | 回环检测在车载场景意义有限 |

### 3.2 VINS的核心优势

1. **紧耦合VIO**: IMU预积分与视觉重投影在统一因子图中联合优化，信息不损失
2. **滑动窗口**: 固定窗口大小(11帧)，计算量恒定，保证实时性
3. **在线标定**: 支持外参、时间偏移在线估计
4. **鲁棒初始化**: 视觉SFM + 视觉-惯性对齐，恢复所有必要状态
5. **可扩展性强**: 因子图框架易于添加新传感器（如轮速计、GPS）

## 四、VINS-simple基本原理和流程

### 4.1 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                      每帧持续运行的并行管线                      │
├──────────────────────────┬──────────────────────────────────┤
│                          │                                  │
```

### 4.2 前端：特征跟踪

**算法**: Lucas-Kanade金字塔光流

- 3层图像金字塔，窗口21×21
- 正向+反向光流验证
- RANSAC基础矩阵验证剔除异常值
- Shi-Tomasi角点补充至MAX_CNT(150)个

**输出**: 7维特征向量 `[x, y, 1, u, v, vx, vy]`

> **通俗理解**：前端就像"眼睛看到什么"。相机每拍一帧，算法就在画面里找一些容易辨认的角点（比如墙角的亮点、标志牌的边缘），然后在下一帧里找到这些点跑到了哪里。通过追踪这些点的移动，就能反推出相机自己是怎么动的。

### 4.3 IMU预积分

**目的**: 将相邻关键帧之间的N个IMU测量压缩为相对运动增量

**中值积分**:
```
ā = 0.5*(a_k + a_{k+1}) - ba
ω̄ = 0.5*(ω_k + ω_{k+1}) - bg

Δq += Δq ⊗ [1, 0.5*ω̄*dt]
Δv += Δq * ā * dt
Δp += Δv*dt + 0.5*Δq*ā*dt²
```

**输出**: Δp, Δv, Δq, 协方差矩阵, 偏差Jacobian

> **通俗理解**：IMU就像人的"前庭系统"（内耳里的平衡器官）。它能感知加速度和旋转，频率高达200Hz，比相机快得多。但IMU的数据是"相对变化"——它只能告诉你"我往前加速了0.5m/s²"，不能直接告诉你"我现在在哪"。预积分就是把两帧图像之间几百个IMU数据压缩成"这段时间我总共移动了多少、转了多少"，方便后面和视觉信息一起算。

### 4.4 系统初始化

#### 4.4.1 视觉SFM重建

1. 选基准帧对 → 5点法求本质矩阵E → SVD分解得R,t
2. 三角化初始3D点
3. 向前PnP扩展 + 三角化
4. 向后PnP扩展 + 三角化
5. 全局BA优化

> **通俗理解**：初始化就是系统"搞清楚自己在哪里、世界长什么样"的过程。视觉SFM通过多帧图像中特征点的位置变化，反推出每帧的位姿和特征点的3D坐标，但这些坐标没有真实尺度——只知道各点之间的相对距离比例，不知道具体是多少米。接着视觉-惯性对齐用IMU的物理测量去和视觉结果匹配，确定重力方向和真实尺度。

#### 4.4.2 视觉-惯性对齐

**Step 1: solveGyroscopeBias()**
- 利用相邻帧旋转约束求解陀螺仪偏置δbg
- 修正后重新积分所有预积分

**Step 2: LinearAlignment()**
- 联合求解: 各帧速度V_i、重力方向g、尺度s
- 约束方程:
  ```
  s*(P_j - P_i) = V_i*dt + 0.5*g*dt² + R_i*Δp
  V_j - V_i = g*dt + R_i*Δv
  ```

**Step 3: RefineGravity()**
- 将重力约束为|g|=9.81（两自由度）
- 在重力切平面上迭代优化

> **通俗理解**：视觉SFM给出了"用眼睛看到的"各帧位置，但这些位置没有真实尺度——你只知道"A帧到B帧的距离是B帧到C帧的2倍"，但不知道具体是多少米。视觉-惯性对齐就是拿IMU的物理测量（加速度、角速度）去和视觉结果"对表"：找出重力方向（哪个方向是"下"）、算出真实尺度（视觉里的"1个单位"等于多少米）、估计每帧的速度。

### 4.5 滑动窗口后端优化

**窗口大小**: WINDOW_SIZE+1 = 11帧

**优化变量**:
| 变量 | 维度 | 说明 |
|------|------|------|
| 位姿 P_i, Q_i | 7(流形6) | 每帧 |
| 速度 V_i | 3 | 每帧 |
| 加速度偏置 Ba_i | 3 | 每帧 |
| 陀螺仪偏置 Bg_i | 3 | 每帧 |
| 特征逆深度 λ_j | 1 | 每个有效特征 |
| 外参 R_ic, t_ic | 6 | 全局 |

**残差项**:
| 残差 | 维度 | 说明 |
|------|------|------|
| 视觉重投影 | 2 | 观测像素 vs 投影预测 |
| IMU预积分 | 15 | 位置/速度/旋转/偏置 |
| 边缘化先验 | 可变 | 来自上一窗口的Schur补 |

**求解**: LM算法 + Schur消元（边缘化路标点，降维求解）

> **通俗理解**：后端优化是系统的"大脑"，每时每刻都在做一道数学题——"调整所有变量，让所有测量之间的矛盾最小"。变量包括每帧的位置、姿态、速度，以及每个特征点的3D坐标。矛盾来自三方面：①视觉说"这个点应该投在像素(320,240)"但实际投在了(322,241)；②IMU说"这两帧之间我移动了0.5m"但视觉算出来是0.48m；③上一轮优化留下的"记忆"（先验）。系统不断微调所有变量，让这些矛盾的总和最小。

### 4.6 边缘化

**目的**: 窗口满时移除老帧，但保留其对剩余变量的约束

**Schur补**:
```
H_prior = H_rr - H_rm * H_mm⁻¹ * H_mr
b_prior = b_r  - H_rm * H_mm⁻¹ * b_m
```

**两种策略**:
- **MARGIN_OLD**: 新帧是关键帧 → 边缘化最老帧
- **MARGIN_SECOND_NEW**: 新帧非关键帧 → 边缘化次新帧

> **通俗理解**：滑动窗口只能装11帧，新帧进来就得扔掉最老的。但直接扔掉等于白算了——老帧里包含的"这两帧之间移动了多少"的信息就丢了。边缘化就是：扔掉老帧之前，先把它对剩余帧的约束"压缩保存"下来，变成一条"记忆"。以后优化时，这条记忆会提醒系统"别忘了，之前老帧说过你们之间应该是这个关系"。

## 五、单目+IMU在车载场景的局限

### 5.1 尺度不可观问题

**核心问题**: 匀速直线运动时，加速度计只测到重力，无法区分"大尺度慢速"和"小尺度快速"

**数学解释**:
- IMU加速度测量: a_meas = R*(a_true - g) + ba + noise
- 匀速时 a_true = 0，a_meas = -R*g + ba + noise
- 尺度s与加速度a_true耦合: s*(P_j-P_i) = V_i*dt + 0.5*g*dt² + R_i*Δp
- 当a_true=0时，s无法从方程中唯一确定

> **通俗理解**：想象你在一条笔直的高速公路上匀速开车，眼睛看着前方。你能感觉到自己在动吗？很难——因为周围景物变化很小，加速度计也只测到重力。这时候系统分不清"我在以50km/h的速度开"还是"我在以100km/h的速度开但世界被缩小了一半"。这就是单目VIO在高速直线场景下的核心困境——尺度（真实世界的"米"）丢失了。

### 5.2 其他局限

| 问题 | 表现 | 原因 |
|------|------|------|
| 尺度漂移 | 长距离累积误差 | 单目尺度不完全可观 |
| 偏置估计退化 | 直线行驶时bg估计不准 | 缺乏旋转激励 |
| 初始化困难 | 静止或纯直线无法初始化 | 需要足够视差和加速度激励 |
| 动态物体干扰 | 定位跳变 | 视觉特征被运动物体污染 |
| 光照敏感 | 夜间/隧道丢失 | 视觉特征提取失败 |

## 六、VIW相对于VINS-simple的优势

### 6.1 核心优势：轮速计提供绝对尺度

**轮速计的本质**: 直接测量车辆在物理世界中的运动速度（m/s），天然具有绝对尺度。

**对比**:
| 特性 | VINS-simple (单目+IMU) | VIW-Fusion (单目+IMU+Wheel) |
|------|------------------------|------------------------------|
| 尺度来源 | IMU加速度积分（需激励） | 轮速计直接测量（始终有效） |
| 尺度初始化 | 需要视觉-惯性对齐 | 轮速计直接提供 |
| 退化运动 | 尺度漂移 | 轮速计约束尺度 |
| 直线行驶 | 尺度不可观 | 轮速计持续约束 |
| 低速/停车 | IMU信噪比低 | 轮速计仍有效 |

> **通俗理解**：轮速计就是车辆的"里程表"——它直接告诉你车轮转了多少圈，换算成"我走了多少米"。这个信息天然带有真实尺度（米），不像单目相机拍出来的只是像素。有了轮速计，系统就像有了一个"尺子"，不再需要费劲地从图像里猜尺度。这就是为什么加了轮速计后，高速直线场景下的定位精度大幅提升。

### 6.2 轮速计处理方式

#### 6.2.1 轮速预积分（WheelIntegrationBase）

**模型**:
```
v_corrected = diag(sx, sy, 1) * v_measured    // 内参校正
ω_corrected = sw * ω_measured                  // 角速度校正
```

**中值积分**（与IMU预积分结构平行）:
```
un_vel_0 = Δq * sv * vel_0
un_gyr = 0.5 * sw * (gyr_0 + gyr_1)
Δq += Δq ⊗ [1, 0.5*un_gyr*dt]
un_vel_1 = Δq * sv * vel_1
Δp += 0.5*(un_vel_0 + un_vel_1)*dt
```

**输出**: Δp, Δq, 协方差, 内参Jacobian (∂Δp/∂sx, ∂Δp/∂sy, ∂Δp/∂sw, ∂Δq/∂sw)

> **通俗理解**：轮速预积分和IMU预积分是"孪生兄弟"——做的事情一样，只是数据来源不同。IMU用加速度和角速度推算位移，轮速计用速度和角速度推算位移。轮速计的优势在于它直接输出速度（m/s），不需要像IMU那样从加速度积分两次（积分会放大噪声）。所以轮速计的位移估计通常比IMU更准。

#### 6.2.2 轮速因子（WheelFactor）

**残差（6维）**:
```
r_p = (Ri*Rio)^T * (Rj*tio + Pj - Ri*tio - Pi) - Δp_corrected   [3D位置]
r_r = log(Δq_corrected⁻¹ * (Qi*qio)⁻¹ * Qj*qio)                  [3D旋转]
```

**参数块（7个）**:
| 参数块 | 维度 | 说明 |
|--------|------|------|
| Pose_i | 7 | 第i帧位姿 |
| Pose_j | 7 | 第j帧位姿 |
| ExtWheel | 7 | 轮速计→IMU外参 (rio, tio) |
| sx | 1 | 前向速度缩放因子 |
| sy | 1 | 横向速度缩放因子 |
| sw | 1 | 角速度缩放因子 |
| td_wheel | 1 | 轮速计时间偏移 |

> **通俗理解**：轮速因子做的事情很简单——它告诉优化器："根据轮速计的数据，第i帧到第j帧之间，车应该移动了这么多、转了这么多。如果视觉和IMU算出来的结果跟这个对不上，那说明哪里算错了，请调整。"sx/sy/sw这三个参数是用来修正轮速计本身的误差的，比如轮胎气压不足导致实际转一圈走的距离比理论值少。

#### 6.2.3 初始化增强

**LinearAlignmentWithWheel**: 在标准6方程基础上增加3个轮速约束方程

```
标准约束 (IMU):
  s*(P_j-P_i) = V_i*dt + 0.5*g*dt² + R_i*Δp_imu
  V_j-V_i = g*dt + R_i*Δv_imu

新增约束 (Wheel):
  (Ri*RIO)^T * (P_j-P_i) = Δp_wheel + RIO^T*Ri^T*Rj*TIO - (Ri*RIO)^T*Rj*TIC + RIO^T*(TIC-TIO)
```

**效果**: 轮速计提供额外的位移约束，使尺度初始化更鲁棒，尤其在视觉退化场景。

#### 6.2.4 内参在线标定

**sx, sy, sw的含义**:
- `sx`: 前向速度缩放（轮胎半径误差、滑移补偿）
- `sy`: 横向速度缩放（通常接近1，地面车辆侧滑小）
- `sw`: 角速度缩放（轴距误差、转弯半径补偿）

**优化策略**:
- 初始值来自标定（sx=sy=sw=1.0）
- 在线优化时使用一阶修正: `Δp_corrected = Δp + J_p_sx*dsx + J_p_sy*dsy + J_p_sw*dsw`
- 与外参优化解耦（当前配置禁用外参在线优化，避免耦合）

### 6.3 因子图对比

**VINS-simple**:
```
[Pose_i]──IMU──[Pose_j]
   │              │
   └──Visual──────┘
        │
   [Feature]
```

**VIW-Fusion**:
```
[Pose_i]──IMU──[Pose_j]
   │    │         │    │
   │    └─Wheel──┘    │
   │                  │
   └─────Visual───────┘
            │
       [Feature]
```

### 6.4 实验验证

基于58个场景的对比实验：

| 配置 | 相对误差均值 | 有效场景数 |
|------|------------|-----------|
| 仅外参优化 | 0.086 | 55/58 |
| 仅内参优化 | 0.112 | 48/58 |
| 内外参同时优化 | 0.145 | 42/58 |
| 无轮速(VINS基线) | 0.180 | 50/58 |

**结论**: 轮速计显著提升精度，但内外参同时优化存在耦合问题，当前最优配置为仅优化外参。

## 七、总结

### VIW-Fusion相对于VINS-simple的核心改进

| 改进点 | 实现方式 | 效果 |
|--------|---------|------|
| **绝对尺度** | 轮速计预积分+因子 | 消除尺度漂移，退化运动鲁棒 |
| **初始化鲁棒性** | 轮速辅助视觉-惯性对齐 | 更快、更稳定的初始化 |
| **内参在线标定** | sx/sy/sw作为优化变量 | 补偿轮胎磨损、胎压变化 |

### 适用场景

- 车载定位与建图
- 自主泊车（高精度近处定位）
- 城市道路导航
- 园区低速自动驾驶
